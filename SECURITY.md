# Security Policy / Политика безопасности

**In short:** report vulnerabilities **privately** via
[GitHub Security Advisories](https://github.com/elcrazycol/gomo6.2/security/advisories/new) —
never in a public issue. Good-faith research is welcome and we will not pursue legal action for it.

**Кратко:** об уязвимостях сообщайте **приватно** через
[GitHub Security Advisories](https://github.com/elcrazycol/gomo6.2/security/advisories/new) —
не в публичном issue. Добросовестные исследования приветствуются, юридических претензий не будет.

---

## Supported versions / Поддерживаемые версии

| Version | Supported | Комментарий |
|---|---|---|
| `main` (latest) | ✅ | Активная разработка, деплоится автоматически |
| Latest release `vX.Y.Z` | ✅ | Прод-инстанс [gomo6.wtf](https://gomo6.wtf) всегда на последнем релизе |
| Older releases / self-hosted without updates | ❌ | Обновляйтесь до последней версии — исправления туда не бэкпортируются |

Версию видно в футере сайта или через `curl -s <url>/health`. Для self-hosted также укажите
commit SHA образа (тег `sha-<commit>` в `ghcr.io/elcrazycol/gomo6-*`).

## Reporting a vulnerability / Как сообщить об уязвимости

1. Откройте **приватный** репорт: **[github.com/elcrazycol/gomo6.2/security/advisories/new](https://github.com/elcrazycol/gomo6.2/security/advisories/new)**
   (вкладка **Security → Report a vulnerability**).
2. **Не** публикуйте детали в issues, PR, комментариях или соцсетях до согласованного раскрытия.
3. Если приватный репорт недоступен — откройте обычный issue **без деталей эксплойта** и попросите приватный канал.

### Что приложить / What to include

- Тип уязвимости и затронутый компонент (`apps/backend-go` / `apps/web` / инфраструктура).
- Пошаговое воспроизведение и, если есть, минимальный PoC (curl, скрипт, HAR).
- Оценку влияния: какой доступ/данные получает атакующий, кто затронут (все пользователи, конкретные, гости).
- Версию/commit и где проверялось: прод `gomo6.wtf` или свой self-hosted инстанс.
- Опционально: предложение по фиксу.

**Не включайте** чужие персональные данные, токены, cookie и приватные ключи. Тестируйте на **своих**
аккаунтах и данных; при необходимости поднимите стек локально (`make dev` — см. `README.md`).

### Чего ожидать / What to expect

| Этап | Срок |
|---|---|
| Подтверждение получения | ≤ 72 часа |
| Первичная оценка и severity | ≤ 7 дней |
| Фикс: критично | ≤ 7 дней |
| Фикс: высоко | ≤ 30 дней |
| Фикс: средне | ≤ 90 дней |
| Фикс: низко | по возможности |
| Публикация Security Advisory | по согласованию, обычно ≤ 90 дней |

Мы согласуем дату раскрытия с вами и укажем вас в advisory (или сохраним анонимность по вашей просьбе).
**Bug bounty нет** — только благодарность и упоминание.

## Scope / Область

### В области / In scope

- **Аутентификация и сессии** — JWT/refresh rotation, CSRF, TOTP 2FA, WebAuthn/passkeys, OAuth2 + PKCE, угон сессии, сброс пароля.
- **Авторизация** — IDOR, обход RLS, ролевые проверки (`authz`), правила постинга на стену, проверки владения объектами.
- **Приватность** — приватные профили, «только для друзей», приватные разделы/темы/стены; утечка priv-контента через поиск, `/api/rpc`, публичные id («цифорки») или тайминги.
- **Мессенджер** — доступ к чужим диалогам, утечка шифротекста или placeholder-обход, фан-аут, ограничения на группы.
- **GomoSub** — доступ к приватным каналам (REST **и** WS room gate), обход прав чтения/записи/модерации.
- **Загрузки и медиа** — обход квот и лимитов, path traversal, подмена content-type, доступ к приватным файлам в S3, обработка изображений.
- **Link preview** — SSRF (private/loopback/link-local/CGNAT), open redirect, утечка внутренних адресов.
- **Realtime** — аутентификация и origin-check WebSocket, утечка чужих событий/комнат.
- **Боты и OAuth-приложения** — утечка токенов, эскалация scope, обход клиентских ограничений.
- **Anti-bot и лимиты** — обход Cloudflare Turnstile, обход rate-limit с реальным влиянием.
- **Веб-векторы** — stored/reflected XSS, CSRF на state-changing эндпоинтах, открытые редиректы.
- **Инфраструктура** — утечка секретов/конфигов, обход миграций, несанкционированный доступ к бэкапам или БД.

### Вне области / Out of scope

- Отчёты автоматических сканеров **без PoC**; CVE в зависимостях без демонстрируемого пути эксплуатации.
- Отсутствие security-заголовков без доказанного влияния, clickjacking на нечувствительных страницах, self-XSS.
- Volumetric DoS/DDoS, brute-force без обхода лимитов, спам, социальная инженерия, физический доступ, malware.
- Проблемы на **зеркалах** (Codeberg, GitLab) — это read-only копии, которые force-push'атся; сообщайте на GitHub.
- Утечки demo-данных из `make seed` на локальном стенде.

### Известные и принятые ограничения / Known accepted limitations

Это не уязвимости — так спроектировано, подробности в документации:

- **Шифрование мессенджера — серверное (AES-256-GCM at rest).** Оператор сервера владеет ключом и может читать переписку. Это **не** Signal-подобный E2E-мессенджер и он так не позиционируется.
- **Нет Perfect Forward Secrecy** — компрометация ключа раскрывает прошлые сообщения.
- Публичные идентификаторы («цифорки») видны по дизайну — раскрытие самого номера не считается утечкой, утечкой считается доступ через него к приватному контенту.

См. [docs/wiki/MESSENGER_SECURITY.md](https://github.com/elcrazycol/gomo6.2/blob/main/docs/wiki/MESSENGER_SECURITY.md) и
[docs/wiki/SECURITY_AUDIT.md](https://github.com/elcrazycol/gomo6.2/blob/main/docs/wiki/SECURITY_AUDIT.md) — там полная модель угроз и статус известных пунктов.

## Safe harbor / Безопасная гавань

Для добросовестных исследований, соблюдающих эти правила, мы не будем инициировать юридические действия:

- работайте только со **своими** аккаунтами и данными;
- не получайте доступ к чужим данным, не изменяйте и не удаляйте их, не закрепляйтесь в системе;
- не нарушайте работу сервиса для других: без агрессивного автоматического сканирования, массовых рассылок и нагрузочных атак;
- не раскрывайте проблему третьим лицам до согласованного срока.

Сомневаетесь, попадает ли действие в рамки — спросите в приватном репорте **до** проверки.
