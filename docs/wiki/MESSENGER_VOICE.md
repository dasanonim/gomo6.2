# Голосовые сообщения в мессенджере

Как устроены голосовые: запись, волна, доставка, воспроизведение и почему
именно так. Код: `apps/web/src/components/messenger/voice.ts`,
`VoiceRecorder.tsx`, `VoicePlayer.tsx`; бэкенд —
`apps/backend-go/internal/messenger` (`validateAudioMeta`).

## Контракт данных

Голосовое — это обычное вложение `type: "audio"` с метаданными:

```json
{ "voice": true, "duration": 12.4, "waveform": [6, 41, 88, ...] }
```

- `voice: true` отличает голосовое от **аудиофайла**: mp3, отправленный
  скрепкой, остаётся строкой файла, а не баблом с плеером.
- `waveform` — 40 пиков `0..100`. Их **присылает отправитель** и получатель
  рисует волну, не скачивая и не декодируя звук. Это правило Telegram (у него
  амплитуды 5-битные): открытие чата с десятком голосовых не должно тянуть
  десяток мегабайт только ради полосок.
- `duration` — секунды, дробные.

Сервер валидирует мету (`validateAudioMeta`): размер JSON ≤ 4 КБ, длительность
`0..600` секунд, не больше 128 пиков, каждый `0..100`. Всё остальное — 400.
Общий лимит вложения — 10 МБ, поэтому запись останавливается на 5 минутах.

## Запись

`MediaRecorder` + `getUserMedia`, контейнер выбирается по возможностям
браузера: `audio/webm;codecs=opus` (Chromium), `audio/ogg;codecs=opus`,
`audio/mp4` (Safari). Расширение файла берётся из mime — от него зависит
ключ загрузки.

Жест (как в Telegram):

| действие | результат |
|---|---|
| нажать и держать | запись |
| отпустить | отправить |
| сдвинуть влево > 110 px | отпускание отменяет |
| сдвинуть вверх > 70 px | «закрепление»: палец можно убрать, запись идёт |
| 5 минут | стоп и отправка сами |

Особые случаи, которые делают запись «безотказной»:

- **Разрешение спрашивается один раз и асинхронно.** Если палец отпустили,
  пока висел запрос, запись всё равно начинается — в закреплённом режиме,
  а не «ничего не произошло».
- **`setPointerCapture` может бросить** (Safari, устаревший pointer id) —
  вызов обёрнут, жест работает через window-слушатели.
- **Меньше 0.6 с не отправляется**: случайный тап не создаёт пустое голосовое.
- **Уход со страницы/вкладки** останавливает микрофон; запись длиннее секунды
  отправляется, а не выбрасывается.
- **Ошибки говорят словами**: нет доступа — «разреши микрофон в настройках»,
  нет устройства — «микрофон не найден», http по LAN — «нужен HTTPS или
  localhost» (`window.isSecureContext`).
- Микрофон доступен только там, где есть `MediaRecorder`; иначе кнопки нет.

## Волна

Две волны, намеренно разные:

1. **Живая** (пока пишем) — `AnalyserNode`, RMS раз в ~70 мс, запись высот
   напрямую в DOM в rAF-цикле. React в кадре не участвует.
2. **Отправляемая** — считается из готового файла (`decodeAudioData` →
   пики по бакетам, мягкая нормализация). Живая волна — приближение: анализатор
   пропускает транзиенты между кадрами, поэтому получатель видит то, что
   реально записалось.

## Воспроизведение

`VoicePlayer` — свой плеер, не `<audio controls>`:

- прогресс пишется в CSS-переменную `--voice-progress` из rAF-цикла, заливка
  волны — `clip-path` на втором слое полосок: ни одного ре-рендера React на
  кадр, только paint;
- текст времени обновляется раз в секунду, а не каждый кадр;
- одновременно играет **одно** голосовое (глобальный указатель на текущий
  элемент);
- скорость 1× → 1.5× → 2× с `preservesPitch`, выбор запоминается в
  `localStorage`;
- тап/протяжка по волне — перемотка, пробел и стрелки — с клавиатуры;
- звук грузится через общий авторизованный blob-кэш (`useAuthenticatedAttachmentUrl`),
  поэтому воспроизведение работает и без публичного доступа к бакету.

**Главная ловушка плеера:** `<audio>` монтируется только после того, как
разрешился blob-URL. Слушатели `play`/`pause`, навешанные в `useEffect`,
подпишутся, пока элемента ещё нет, и не подпишутся никогда — звук играет,
а иконка и прогресс стоят. Поэтому они — React-пропсы на элементе
(`onPlay`/`onPause`/`onEnded`/`onError`), и на это есть регрессионный тест.

## Побочные детали

- В списке чатов сообщение без текста превьюится как «Голосовое сообщение»
  (бэкенд пишет это в `last_message_preview`, клиент повторяет для входящих по
  WS).
- Цитата голосового в ответе показывает «Голосовое сообщение», а не пустоту.
- Бабл с голосовым получает класс `is-voice-bubble`: своя ширина, а
  время/статус не пытаются встать инлайном поверх плеера.

## Как проверить руками

1. Разрешить микрофон для `localhost`.
2. Пустой композер → кнопка микрофона; нажать и держать 2–3 секунды, отпустить.
3. Проверить отправку, волну, время, проигрывание, скорость и перемотку.
4. Сдвинуть влево при записи — отмена; вверх — закрепление и кнопка отправки.
5. На телефоне запись требует HTTPS (`make mobile` подсказывает), иначе браузер
   не даёт `getUserMedia`.
