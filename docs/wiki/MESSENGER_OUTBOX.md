# Messenger outbox — офлайн-очередь отправки

Сообщение принадлежит автору с момента нажатия «отправить». Очередь делает это
буквально: сообщение попадает в чат сразу (часики вместо галочки), уходит на
сервер при первой возможности и переживает перезагрузку страницы.

## Что видит человек

| Состояние | В пузыре | В очереди |
|-----------|----------|-----------|
| отправляется | часики (`Clock`, `.status-clock`) | есть, `gaveUp: false` |
| доставлено | галочки | нет |
| не ушло | красный `!` (`!`, `.status-failed`) + «Не отправлено · Повторить» | есть, `gaveUp: true` |

«Повторить» вызывает обычный `sendMessage(content, client_id)`: пузырь
заменяется на месте (тот же `client_id` → та же строка списка), запись в очереди
обнуляется. Удаление неотправленного сообщения убирает запись из очереди, иначе
ретрай воскресил бы пузырь.

## Где живёт

- `apps/web/src/components/messenger/core/outbox.ts` — очередь.
  Своя IndexedDB (`gomo6-messenger-outbox`), а **не** база кэша сообщений: её
  `onupgradeneeded` пересоздаёт store при смене версии, и отложенная почта не
  должна стать побочным уроном. Рядом in-memory `Map` — private mode и jsdom
  работают без IndexedDB.
- Ключ записи: `ownerId:conversationId:clientId`. Чужая учётка очередь не видит:
  `listOutbox(ownerId)` фильтрует, `destroyMessenger`/выход её чистит.
- В записи лежит **plaintext**; заметки шифруются заново на каждой попытке
  (`e2enote1:`), поэтому ключ устройства никуда не уезжает.
- Вложения уже загружены в S3 — в очереди только метаданные, повторная отправка
  не перезаливает файлы.

## Пачка сообщений не ждёт предыдущего

Как в Telegram: `handleSend` очищает композер **сразу** и не ждёт сервер. Пузыри
появляются мгновенно, каждый со своими часиками, ввод и отправка дальше не
блокируются (`isSending` больше не гейт — только косметический класс).

Порядок при этом не страдает:

- `serializeSend(convId, task)` — цепочка промисов **на чат**: запрос N+1 не
  уйдёт раньше, чем завершится N. Параллелить запросы нельзя: сервер ставит
  `sent_at` в момент вставки, и пачка из трёх сообщений прилетела бы
  перемешанной.
- Запись в очереди берётся **в лиз** (`OUTBOX_LEASE_MS = 30s`,
  `nextAttemptAt = now + лиз`) на время инлайн-попытки, поэтому `flushOutbox` не
  отправит её повторно. Если вкладку убили посреди запроса, лиз истекает и
  очередь подхватывает сообщение сама.
- Возврат `sendMessage` для вызывающих: id сервера → доставлено,
  `temp_<clientId>` → в очереди (композер очищен, альбом идёт дальше),
  `""` → отказ (4xx): только тогда черновик/вложения остаются у человека.
  `ShareSheet` поэтому не имеет права подставлять `temp_…` в
  `parent_message_id`.
- «Повторить» на failed-сообщении переотправляет и вложения
  (`onRetry` передаёт `m.attachments`), иначе голосовое/фото ушло бы пустой
  подписью.

## Ретраи

- `OUTBOX_MAX_ATTEMPTS = 6`, пауза `2s → 4s → 8s → 16s → 30s → 30s`
  (`outboxRetryDelay`). После шестой — `gaveUp`, дальше только вручную.
- `isPermanentSendError` — 4xx, кроме 401/408/429: 400/403/404/413/422 не пройдут
  никогда, поэтому попытки не тратятся, пузырь сразу failed.
- Сигналы к разбору очереди: `online`, `visibilitychange → visible`, `init()`
  (после логина) и таймер до ближайшего `nextAttemptAt`. Простоя не бывает:
  пустая очередь не держит таймер.
- Порядок FIFO **внутри чата**: запись, которая ещё не «созрела» или упала,
  блокирует только свой чат — остальные уходят.

## Инварианты, которые легко сломать

- `s.messages` — сообщения **открытого** чата. Ни `sendMessage`, ни `flushOutbox`
  не пишут в `cacheCurrentMessages`/`rememberLatestEventId`, если
  `conversationId !== selectedConversationId`: иначе история другого чата
  затрётся кэшем открытого.
- Сообщение из очереди показывается в чате даже до ответа сервера:
  `loadMessages` мержит записи через `withOutboxEntries` (by `client_id`), поэтому
  перезагрузка не теряет ни пузырь, ни его время.
- Сервер дедуплицирует по `UNIQUE(conversation_id, client_id)` и возвращает
  существующую строку — потерянный ответ не даёт дубль при ретрае.
- Отправка в фоне (с `conversationId` другого чата) не вставляет оптимистичный
  пузырь в открытый чат: сообщение придёт эхом по WebSocket.
